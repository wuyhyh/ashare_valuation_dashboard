# v0.9 · 沪深主板市场宽度快照数据审计

## 目标与已编码边界
本版只在用户显式运行 `breadth-update` 时抓取沪深京 A 股**行情快照**，用代码前缀初筛沪深主板，再与上交所主板 A 股名录和深交所 A 股列表中的主板股独立核对。默认 `auto` 按东方财富、腾讯、新浪有界尝试，一次更新只使用一个成功行情源，不拼接不同提供方的股票行。

- 初筛沪主板：`600 / 601 / 603 / 605`；深主板：`000 / 001 / 002 / 003`。每次真实更新要求沪、深各自对官方名录的代码覆盖率均不低于 95%。
- 排除 B 股、ETF、创业板、科创板、北交所与无法识别代码。
- 包括风险警示股票的“主板全部样本”与排除 ST / 退市风险股票的“可交易参考样本”分别统计。
- 返回了有效价格/涨跌幅/成交额但成交额为零者单列，不等同于价格平盘，也不直接推断其属于停牌。
- 上涨比例分母：有真实报价与正成交额的所选样本；不是交易所全部挂牌家数。
- **采集时间不等于交易日期。** `captured_at_utc` 和 `capture_local_date` 仅为本地采集时刻；目前 `trading_date=None`、`trading_date_verified=False`，不能仅凭周末抓取重播旧行情形成周末“市场宽度”。
- 历史时间曲线尚未激活；须建立可信的交易日/收盘时点确认、完整股票池及连续快照记录。

## 数据安全
- 新快照保存在项目根目录 `breadth.sqlite3`，与原 `valuation.sqlite3` 完全独立，两者均由 `.gitignore` 排除。
- 同一天不同采集时间保留独立 `capture_id`，不会偷偷去重成某个臆造的收盘交易日。
- 网页 `/api/breadth` 为只读，启动 `python app.py` 不会自动联网采集。
- 本地 CSV 受控导入、可核验交易日与收盘时点、历史可比快照/移动均线宽度和行业估值分布尚未实现。


## 自动化数据完整性防护（2026-11-01）
- 三个行情提供方均用受控子进程与有界尝试，先消耗结果队列再回收进程，避免大量股票行因 IPC 缓冲塞满而卡住。
- 更新前比较上一份**相同来源**主板识别数量：若旧样本不少于1000条且本次不足其80%，拒绝激活并保留旧快照。这是可疑截断保护，**不是对交易所全量挂牌股票的证明**。
- 真实腾讯快照与两所名录核验已完成；东方财富限流仍是外部风险。
- 新增 `tests/browser_breadth.py` 的空库、沪深切换、ST筛选与390px页面冒烟；脚本使用模拟API，不能当成真实市场快照验收。
- `tests/browser_v09_real.py` 已在本机真实 `breadth.sqlite3` 上验收桌面端、390px、交易所覆盖与零 JS 错误；该脚本不进入无私有数据的 CI。
