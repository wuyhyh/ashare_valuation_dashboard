# v0.11 · 历史市场宽度来源核验审计（Phase A）

> 当前状态：**只实现可信序列的只读模型与空状态，尚无真实已核验历史收盘快照**。下文的两天历史为 TEST FIXTURE，仅用于验证程序行为，不能引用为2026年的市场事实。

## 来源背景
- v0.10 使用腾讯/AkShare即时报价和当时上交所、深交所、北交所证券名单逐板块交叉核验，确保采集时点股票身份；即时API没有可独立核验的报价交易日，也没有已证明的一致收盘价。
- v0.9主板旧快照以 `mainboard_only` 保存；v0.10沪深全A股和BSE有不同 `coverage_scope`，不得在历史趋势里混用。
- 2026-11-01周日取得的原始横截面不应当自动标成2026-10-30收盘，无法直接构造多年历史。

## Phase A 代码设计
- 实现 `breadth_history.breadth_trend()` 与只读HTTP `GET /api/breadth-trend?scope=SH_SZ_ALL&exclude_st=0&limit=90`；scope使用现有 `SCOPE_BOARDS`，窗口2—180。
- SQLite通过 `file:...?...mode=ro` 读取，不调用会修改表的 `breadth.open_db()`；无库、旧库、零条验证、仅一条验证均显式返回不可绘图。
- 单一曲线只选同 `source_interface`、`coverage_scope`、`calculation_version`、scope、ST口径的可信样本；同日多个合格捕获取最新。曲线按真实交易日排序，超过7个自然日的日期缺口不画连续线。
- 可信记录不只要求 `trading_date_verified=1`；还要满足 `quality_json.close_verification`：
  - `status=passed`、`method=independent_stock_daily_close_crosscheck`；
  - `calculation_version=v011-breadth-v1`，独立参考来源非空，参考交易日等于记录交易日；
  - 当天北京时间15:30之后采集，且采集本地日就是独立核验的交易日；
  - `checked_samples >= 20`、`matched_samples >= 20`、匹配率>=95%；
  - `max_relative_diff <= 0.0005`（即相对差0.05%）；
  - `checked_boards` 覆盖所选市场范围的全部板块，各板块 `official_pool.boards[board].coverage_ratio >= .95`。
- `advance_ratio` 仍用各板块真实有效成交样本分母。暂不生成5/20日平滑指标，也不从估值月频插值得出日频市场相对价值。

## Phase A 离线模拟验收范围
- 将模拟收盘证据标注 `TEST FIXTURE ONLY`，验证真/假标记、匹配比例不足、同日收盘前、参考日期不同、同一天去重、不同报价源不拼接、主板旧口径不冒充全市场。
- 浏览器模拟接口验证**无可用历史时不显示线**、两条有模拟证据的交易日出现图表、390px不横向溢出。
- 所有数据和截图仅作为程序行为检查，不是对真行情供应商的验证。

## 需要 Codex 继续推进的真实验收（Phase B）
1. 在联网 macOS 上确定独立“逐股交易日收盘”参考源并实际检查其返回日期、收盘价、前收盘价、停牌/零成交口径、股票代码及交易所；需要覆盖沪主板、深主板、创业板、科创板，北交所另行要求。
2. 编写显式的收盘后验证入口，参考源的逐股日线与主源**同一交易日**核验，保存 reference_source、交易日与检查证据；无法核验则继续拒绝。
3. 每次只保留有证据的收盘快照；日间及周末快照不冒充收盘。真实历史观测的起点等于首次可信上线日期，不允许使用今天的成员名单回填十年前的涨跌家数。
4. 至少取得两个真实不重合的交易日，记录来源字段、逐板覆盖、差异分布、各项测试和截图；未经这些证据不能声称真实历史趋势就绪。
5. 在 Phase C 开始估值联动前，先确认宽度交易日与乐咕**月频** PE/PB日期的真正交集；禁止前向填充、移动配对窗口和模拟相关性。

**结论**：Phase A 是实现基础能力、定义可信标准；目前对用户的真实性结论仍为“历史宽度不可用，等待真实逐股收盘核验”。
