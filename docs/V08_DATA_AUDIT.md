## 真实身份与点位核验

- 中证官方接口逐条返回并通过代码校验：`000016 / 上证50 / 上证50指数`、`000905 / 中证500 / 中证小盘500指数`、`000852 / 中证1000 / 中证1000指数`。
- 三个指数的官方收盘与新浪日线在最近 5 个共同交易日交叉验证通过，最大绝对相对差分别为 `0.000181%`、`0.000048%`、`0.000075%`。
- 乐咕 PE/PB 中的数值型“指数”列与已激活的官方收盘在最近 5 个共同月末完全一致；共同日期数分别为上证50 `262`、沪深300 `130`、中证500 `238`、中证1000 `145`。
- 该交叉验证只作为指数身份的辅助证据，不证明乐咕估值计算细节与官方口径相同。质量结果写入活动序列 `quality_json.source_identity`，严格比较会拒绝已记录但未通过的身份核验。

## 实测命令（在 Mac 本地运行）

```bash
python app.py diagnose --index 000016 --metric all
python app.py diagnose --index 000905 --metric all
python app.py diagnose --index 000852 --metric all

python app.py diagnose-market --index 000016 --provider csindex_official --cross-check sina --start 20050101 --end 20261030
python app.py diagnose-market --index 000905 --provider csindex_official --cross-check sina --start 20070101 --end 20261030
python app.py diagnose-market --index 000852 --provider csindex_official --cross-check sina --start 20140101 --end 20261030
```

已按上述顺序先诊断、备份 SQLite，再显式激活三条官方收盘和八条乐咕估值序列。批量估值更新每次请求间隔 2 秒；遇到 HTTP 429 时采用较长退避，避免连续冲击上游。

如批准后执行 `python app.py update --index all --metric all`，逐项核对 `/api/coverage` 和 `/api/comparison?metric=pe_ttm` / `pb`，检查是否存在不同口径、历史截断、共同日期错位或缺失样本。

## 乐咕“指数”字段的身份验证结论

乐咕 PE/PB 的 `指数` 字段实测为**数值型指数点位**，并非指数名称或代码。代码不会做错误的字符串身份比较，而是与独立指数收盘按真实同日交叉校验最近 5 个样本。若上游字段、频率或点位出现偏差，严格比较状态会降级并给出警告；不会默认为指数身份正确。

## 估值口径边界

- 乐咕 PE 固定取 `stock_index_pe_lg` 的 `滚动市盈率`；PB 固定取 `stock_index_pb_lg` 的 `市净率`。
- 中证官方 `stock_zh_index_hist_csindex` 的 `滚动市盈率` 是**独立日频系列**；上证50和中证500有效值从 `2011-06-28` 开始，均为 3661 条，中证1000从 `2014-01-02` 开始为 3118 条。
- 2026-10-30 官方/乐咕 PE 分别为：上证50 `11.20 / 11.00`，中证500 `21.59 / 21.72`，中证1000 `25.08 / 24.06`。频率、缺失结构和数值均有差异，绝不自动替换或拼接。
- 历史百分位仅指各指数相对其自身历史的排序，不是四个指数之间的绝对价值排名。
- 当前本机四指数 PE 与 PB 都以 `2026-10-30` 为最新共同日期，来源、字段口径、月频和身份交叉核验一致，`strict_comparison=true`。新 clone 没有数据库时仍会明确显示数据缺失。
